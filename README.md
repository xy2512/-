## 1. 项目背景与目标

### 1.1 项目背景
在高校校园及年轻人群体中，存在大量“技能溢出”与“技能学习”的不对称需求。传统的家教或培训机构门槛高、距离远、非标准化技能（如游戏陪练、摄影入门）难以覆盖。本项目旨在通过 LBS（地理位置服务）和去中介化的交易模式，构建一个轻量级的技能交换网络。

### 1.2 产品目标
*   **核心价值**：打造大学生群体的技能变现与低成本学习闭环。
*   **商业模式验证**：通过“首单抽佣、续单免佣”的模式，降低平台跳单风险，建立初始信任。
*   **体验目标**：实现从“发现-预约-交付-支付”的全流程线上化，提供可视化的时间管理工具。

### 1.3 用户画像
| 用户角色 | 核心特征 | 核心诉求 |
| :--- | :--- | :--- |
| **技能分享者 (老师)** | 大学生、自由职业者 | 课余时间变现、积累教学经验、社交拓展 |
| **技能需求方 (学员)** | 18-28岁年轻人 | 低成本学习新技能、寻找附近靠谱的老师 |

## 2. 产品范围

### 2.1 功能架构图 (Feature Map)
*   **用户端**：微信一键登录、实名认证、LBS定位、技能发布/管理、课程预约、订单管理、即时通讯。
*   **后台管理**：用户审核、技能内容风控、订单仲裁、资金结算。

### 2.2 核心策略
*   **交易策略**：首单平台担保并抽佣 10%，后续课程允许脱离平台或平台免佣支付（旨在降低跳单对平台的损害，顺应C2C交易习惯）。
*   **风控策略**：强制实名认证（涉及资金往来），评价体系互评机制。

## 3. 核心业务流程

### 3.1 首次预约与交易流程 (泳道图逻辑描述)
> **说明**：这是本产品的核心差异化逻辑，重点在于“先课后付”与“首单分账”。

1.  **学员**：浏览老师详情 -> 发起私聊咨询 -> 确认意向。
2.  **老师**：在【课程表】设置“可预约”时间段。
3.  **学员**：选择时间段 -> 发起预约（无需预付，状态：`待上课`）。
4.  **线下/线上**：双方进行教学交付。
5.  **学员**：小程序端确认“下课” -> 发起支付（状态：`已完成`）。
6.  **系统**：
    *   自动分账：扣除 10% 平台服务费。
    *   结算：90% 资金进入老师绑定的微信账户。
    *   记录：标记该师生关系为“已成交”，后续预约免除佣金。

### 3.2 异常处理流程
*   **爽约/未支付**：若学员课后未支付，老师可发起【投诉/仲裁】，提交聊天记录或上课证据，平台介入封禁学员账号或限制功能。

## 4. 功能需求详情

### 4.1 账户与安全模块
| 页面/模块 | 功能点 | 详细逻辑说明 |
| :--- | :--- | :--- |
| **登录/注册** | 微信授权 | 获取 OpenID、头像、昵称；新用户自动创建账户。 |
| **实名认证** | 身份核验 | **前置条件**：发布技能或支付前必须完成。<br>**逻辑**：调用实名接口或上传证件（MVP阶段可人工审核），确保交易合规。 |
| **LBS定位** | 位置获取 | 1. 自动定位：获取经纬度，反解析为省市区。<br>2. 手动切换：支持用户手动修改当前浏览区域。 |

### 4.2 技能发布与管理
*   **技能分类**：系统预设一级分类（运动、艺术、语言、IT），支持自定义标签。
*   **发布字段**：
    *   标题（20字内）
    *   图文详情（支持多图上传）
    *   授课方式（线上/线下/不限）
    *   **价格策略**：单位支持“元/小时”或“元/次”。
*   **审核机制**：发布后状态为`审核中`，后台通过后转为`已上架`。涉及敏感词自动拦截。

### 4.3 预约与时间管理 (核心亮点)
*   **可视化课表**：
    *   **交互**：采用日历/周视图。支持**拖拽**或**点击**格子来选择时间段。
    *   **老师端**：点击空白处 -> 标记为`闲置/可约` -> 支持批量设置（如：每周一三五 19:00-21:00）。
    *   **学员端**：仅展示老师标记为`可约`的时间段 -> 点击即锁定 -> 生成预约单。
*   **冲突检测**：同一时间段已被预约，其他学员不可见或置灰。

### 4.4 订单与支付系统
*   **订单状态机**：
    *   `待上课`：预约成功，服务未开始。
    *   `待支付`：服务结束，学员确认。
    *   `已完成`：支付成功，资金结算。
    *   `售后/仲裁`：发生争议。
*   **支付分账**：
    *   判断逻辑：`IF` (师生关系 == 首次交易) `THEN` (平台抽佣 10%) `ELSE` (平台抽佣 0%)。

### 4.5 评价体系
*   **双向互评**：订单完成后，双方可在 7 天内互评。
*   **信用分影响**：差评将扣除用户信用分，信用分低于阈值将限制发布技能或降低推荐权重（搜索排名靠后）。

## 5. 非功能性需求 (NFR)

### 5.1 性能要求
*   **首屏加载**：小程序首屏渲染时间 < 1.5秒。
*   **LBS响应**：附近的人/技能列表加载延迟 < 1秒。

### 5.2 安全要求
*   **资金安全**：接入微信支付分账系统，确保资金流合规，不涉及平台二清。
*   **内容安全**：接入微信文本内容安全检测接口（msgSecCheck），过滤涉黄涉政信息。

## 6. 数据埋点需求 (Data Tracking)

为了验证产品迭代方向，需统计以下核心指标：
*   **转化漏斗**：技能详情页浏览UV -> 点击“立即预约”UV -> 预约成功UV -> 支付成功UV。
*   **核心业务指标**：
    *   **复购率**：同一对师生进行第二次交易的比例（验证“续单”逻辑是否有效）。
    *   **履约率**：预约后完成支付的订单比例。
    *   **搜索热词**：统计用户高频搜索的技能关键词，用于优化分类设置。
